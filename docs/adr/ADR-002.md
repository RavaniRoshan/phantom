# ADR-002 — Typed action schema v2 with fail-closed validation

**Status:** Accepted (2026-11-18)
**Work item:** W0.2 (strict normalization now), W0.4 (per-action typed params — deferred)
**Context:** DEV-PLAN §6; W0.2/W0.4.

## Context

`normalize_action_dict` used to default missing `action_type`/`action` to
`"done"` with confidence 1.0. An empty or malformed model response therefore
became a completed task: the central "false success" defect. Params were a
stringly-typed `map<string, string>`, so wrong-typed parameters silently
degraded into no-ops.

## Decision

**Phase 0 (this change):**
1. `normalize_action_dict(d, *, strict=True)` is the default and the **only**
   mode used on the live path. Missing, empty, or invalid `action_type`/`action`
   raise `ActionValidationError(ValueError)`.
2. `done` is never inferred; it requires explicit model intent
   (`action_type == "done"` and `action == "done"`).
3. The gRPC server re-normalizes strictly at the boundary and maps `ValueError`
   to `INVALID_ARGUMENT`.
4. The Rust client treats `INVALID_ARGUMENT` as permanent, retries at most once
   on transient errors, then propagates a task error (W0.13).
5. `strict=False` remains only for offline tooling and is documented as such.

**Phase 1 (deferred to W0.4):** replace `map<string,string>` with per-action
typed params validated on the Rust side before execution. The strict boundary
established here is the prerequisite.

## Consequences

- A malformed-output corpus (100 cases) yields zero false `done` results.
- Providers that cannot parse a tool call now fail the step instead of faking
  completion; the daemon/TUI surface a real error.
- Existing lenient tests were updated to assert the fail-closed behavior.
