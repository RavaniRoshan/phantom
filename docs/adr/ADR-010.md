# ADR-010 — Hyper-V golden image with an in-guest control agent

**Status:** Accepted (2026-11-18)
**Work item:** B0.3/B4 (see `docs/BETA-BUILD-PLAN.md`)
**Context:** ADR-008 chose an isolated VM; the concrete provider was undecided.

## Context

The hidden-desktop backend produced all-black captures in three smoke runs. Microsoft's Windows Agent Arena (MIT) demonstrates the fix pattern: a Windows 11 golden image, a **Python server inside the guest** that receives agent commands, screenshot delivery through a host viewer, and optional UIA/Set-of-Marks grounding (source: https://github.com/microsoft/WindowsAgentArena). OSWorld's host–client design injects secrets at VM startup rather than baking them into the image (source: https://github.com/xlang-ai/OSWorld). Hyper-V is built into Windows 10/11 Pro/Enterprise (not Home) (source: https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/install-hyper-v).

## Decision

1. Build a **Windows 11 Enterprise Evaluation** golden VHDX (90-day ISO, rebuilt before expiry) with autologon and a Rust `phantom-guest` service.
2. `phantom-guest` runs in the VM's real console session. It owns capture (DXGI Desktop Duplication or GDI on the console session), input (SendInput/UIA), UIA tree dumps and artifact upload. The host **never** calls `PrintWindow` against a guest window.
3. Host and guest communicate over an internal virtual switch with token auth and a frame budget (1080p, ~10 fps).
4. Implement `VmBackend` for Hyper-V (create/restore/start/stop) behind the existing `VmPool`; add a Cloud PC adapter behind the same trait for hosts without Hyper-V.
5. Each task restores a clean checkpoint; secrets are injected at startup, never stored in the golden image.

## Consequences

- Guest agent is a new Rust binary shipped inside the golden image; image build is a scripted, repeatable artifact.
- B0.3 is a hard gate: if the guest agent returns a black frame, GUI work stops and the VM approach is re-scoped again.
- Windows Home users require the Cloud PC adapter; that path is second priority.
- VM lifecycle, cost and pool sizing remain first-class (W8/ADR-008).

## Verification corrections (2026-11-18)

- Hidden-desktop and disconnected-RDP capture failures are fundamental (no paint calls on an inactive desktop; blank frames on disconnect), not fixable with flags. RDP becomes a **human viewer transport** only.
- Capture order is now **Windows.Graphics.Capture → GDI BitBlt fallback**; DXGI Desktop Duplication is an optional fast path with a mandatory fallback because it produces black/zero frames in some GPU/RDP contexts.
- Microsoft's Windows 365 for Agents validates the design (Create/Get/Do/See planes, on-box agent, MCP action API with 72 tools, WebRTC human observation on a separate link). Desktop coordinates are screen pixels; browser coordinates are CSS viewport pixels — never interchange.
- Keep the Hyper-V synthetic display primary; a dummy plug or IddCx display may be needed when headless, but an added VDD can break the VMConnect viewer.
- Each Windows guest needs its own license; evaluation images are 90/180-day and not for customer-facing production. Resolve licensing before external beta.
