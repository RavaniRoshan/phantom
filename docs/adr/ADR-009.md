# ADR-009 — Tauri GUI plus an authenticated local control plane

**Status:** Accepted (2026-11-18)
**Work item:** B1/B2 (see `docs/BETA-BUILD-PLAN.md`)
**Context:** beta users need a Windows app, not a terminal.

## Context

The TUI embeds `phantom-core::Agent` directly and the daemon only accepts webhook/file triggers. There is no API a GUI can call to submit, observe, approve or cancel tasks, and no way for a background task to survive closing a window. Tauri 2 uses the OS web renderer and a Rust backend, so the existing agent, store, policy and VM crates can be reused without a second language runtime (source: https://tauri.app/). Codex's shipped pattern separates the *sandbox* (what is reachable) from *approvals* (when to pause), exposed as a mode control below the composer (source: https://developers.openai.com/codex/permission-modes).

## Decision

1. Add a new crate `phantom-control`: an authenticated loopback HTTP + WS/SSE server owned by the daemon. It exposes tasks, cancel, approvals, artifacts, settings, VM status and a live event stream.
2. The daemon owns agent instances and task state; the GUI is a client. This preserves background operation and tray behaviour.
3. Build the Windows app with **Tauri 2** (Rust commands bridging to `phantom-control`, web frontend for the UI). Electron is the runner-up if the streaming UI proves too constrained.
4. The app has six surfaces: tray, main window (composer + tasks + live VM viewer), approval modal, history/artifacts, settings, first-run wizard.
5. Mode labels mirror Codex: Ask for approval / Auto-approve safe / Full access, each paired with an explicit capability scope.

## Consequences

- A new crate and a new workspace member (`apps/phantom-app`); CI must build both.
- The webhook remains for external triggers and keeps its own token; the GUI uses the control-plane token.
- GUI work is blocked until the VM guest-agent spike (ADR-010) proves capture works.

## Verification corrections (2026-11-18)

- The claim that Codex/Claude Desktop ship Electron is **community-reported**, not confirmed by an official engineering post; Electron remains the runner-up on that softer evidence.
- Tauri's Windows tray/toast path has open bugs (notification permission forced to denied, tray restore/menu/icon issues) and its notification plugin only works for installed apps — B0.2 must verify these in a clean VM rather than assume they work.
- Tauri IPC is JSON-serialized: token and frame streams must be batched.
- Windows 10 reached end of support 2025-10-14; Win11-first is acceptable.
- Electron tray GUID nuance: signed exe → GUID survives path changes; unsigned → GUID tied to executable path.
