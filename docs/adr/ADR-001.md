# ADR-001 — Image transport: PNG normalized at capture, MIME carried in the contract

**Status:** Accepted (2026-11-18)
**Work item:** W0.1
**Context:** DEV-PLAN §6; the five LLM providers each hard-coded `"image/png"`
and the desktop backend returned a 24-bit BMP that providers labelled as PNG.

## Context

The desktop capture path produced BMP bytes; the providers wrapped whatever
bytes they received in `data:image/png;base64,...`. A BMP mislabelled as PNG is
rejected (or silently misread) by vision models. In addition, a failed capture
was returned as an all-black BMP with `Ok(())`, producing a plausible-looking
but fake observation (the "false success" defect).

## Decision

1. **Normalize at the source.** `VirtualDesktop::screenshot()` returns a typed
   `Image { bytes, mime, width, height }`, encoded to **PNG** in Rust via the
   `image` crate. The magic bytes are asserted (`Image::is_png`).
2. **Carry the MIME in the contract.** `ActionRequest.screenshot_mime` (field 7,
   forward-compatible) is set by the Rust agent from `detect_image_mime()`.
3. **Providers honor the contract.** `python/phantom_llm/vision.py` is the single
   shared helper (`encode_image`, `effective_image_mime`, `detect_image_mime`).
   All five providers call it; no provider hard-codes a media type.
4. **Fail closed on bad captures.** `PrintWindow` and `GetDIBits` return values
   are checked; the bitmap is deselected before `GetDIBits`; the `BitBlt`
   self-copy is removed; and an all-black frame is a typed error (W0.12).
5. Model-side downscaling remains a later concern; the contract is independent
   of image size.

## Consequences

- All providers see a single, provider-compatible image format.
- Contract tests assert magic bytes and MIME on both sides of gRPC.
- Adding JPEG/WebP later requires no provider changes — only the capture side
  and the declared MIME.
- Stale generated Python stubs are tolerated via `getattr(request,
  "screenshot_mime", "")`; regenerate stubs to send the field.
